# Importer fixtures

Ground truth for `graphghan import` (#17, #108): PDFs whose every cell is already known.

## Our own PDFs, committed

`<slug>-<key>.pdf` is `graphghan export --format pdf` over the committed
`patterns/<slug>/dist/charts/<key>/chart.json`, one per published chart of every pattern.
Generated by `generate.py` (run `uv run python fixtures/import/generate.py`); the exporter is
byte-reproducible, so `tests/test_import_fixtures.py` fails when a committed file differs from a
fresh generation, the same contract as `fixtures/chart-format/`.

The layout is described in
`docs/superpowers/specs/2026-09-19-pattern-pdf-import-export-design.md` §4. The importer reads
three grammars back from the text layer, fixed as constants in `graphghan/pdf.py`: the chart
page header (`Chart k of n: columns a-b of W, rows c-d of H`), the key rows (`code  name  #hex
yarn`), and the written rows (`export.written_rows`). Changing any of them is an importer change.

## Real PDFs, never committed

`real/` (added with the importer) holds pattern PDFs and chart images that belong to other people.
They are gitignored; only a manifest of ids, source URLs and expected dimensions is committed,
and a test that cannot find a file skips and says so. See `docs/research/corpus/sources.md` for
where each comes from.
