# Bundle fixtures

`<slug>.graphghan` is `graphghan export <slug> --format graphghan` over the committed
`patterns/<slug>/dist/`, one per pattern: a zip holding `pattern.json` plus exactly the files that
manifest references. Generated by `generate.py` (run `uv run python fixtures/bundle/generate.py`);
the writer is byte-reproducible, so `tests/test_bundle_fixtures.py` fails when a committed file
differs from a fresh generation, the same contract as `fixtures/chart-format/` and
`fixtures/import/`.

These are the iOS side's only real input. `GraphghanCore`'s `PatternBundleTests` opens one and
loads every chart through `Chart.load`; the app's `BundleImportTests` imports one into an
in-memory library. The format and the reproducibility decisions (stored entries, a fixed 1980
timestamp, a fixed manifest `updated`) are in
`docs/superpowers/specs/2026-09-19-open-graphghan-bundles-design.md` §2 and §3.2.

A committed binary makes `blink review` refuse the diff; review a branch carrying one on a scratch
branch with these files excluded (repo `README.md`, "Agent code review").
